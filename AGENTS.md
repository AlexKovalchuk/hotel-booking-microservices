# Контекст навчання та розвитку

Узгоджено з користувачем 2026-10-16. Це контекст для подальшої роботи,
а не фіксований план чи оцінка поточного рівня за самим лише кодом.

## Ціль і підхід

- Користувач розвивається як Senior Backend / .NET developer.
- Hotel Booking — основний практичний проєкт для навчання.
- Допомагати формувати й коригувати план розвитку, коли це потрібно,
  спираючись на актуальний прогрес проєкту, виявлені прогалини та фідбек співбесід.
- C#/.NET, EF Core та SQL — основа; Azure Developer — обраний користувачем
  напрямок хмарної спеціалізації (уточнено 2026-10-20).
- Поглиблювати розуміння рішень, їхніх компромісів і поведінки при збоях.
  Не додавати технології чи сервіси лише заради кількості.

## Вихідні знання та пріоритети

- Користувач прямо уточнив: SQL практично не знає. Починати з основ,
  не припускати впевненого знання SQL через використання EF Core.
- Вивчати SQL на практичних задачах Hotel Booking, пов'язуючи LINQ/EF Core
  зі згенерованими запитами та їхнім виконанням. Поступово пояснювати JOIN,
  агрегації, індекси, транзакції та конкурентний доступ у контексті задач.
- На момент узгодження користувач підтягує EF після співбесіди з Avenga.
- Є також великий список питань від Luxoft; повний список у цьому репозиторії
  не зафіксований. Не вигадувати його вміст.
- У наданому фідбеку співбесіди відзначено прогалини в code review,
  колізіях хеш-таблиць, делегатах, деталях JWT, stored procedures,
  метриках кешу, тестуванні HttpClient та Dependency Inversion.
- Приділяти увагу практиці code review: знаходити проблеми, пояснювати
  наслідки та обґрунтовувати виправлення.

## Сертифікації та стан проєкту на момент узгодження

- Користувач вивчає AZ-900 і хоче завершити його. Подальші Azure developer
  та architect сертифікації — можливий напрямок, без фіксованого графіка.
  Перед рекомендаціями перевіряти актуальність іспитів і вимог.
- На 2026-10-16 у коді є Identity, Hotels і початок Search; робота з EF Core,
  ролями/власниками ресурсів та HttpClient. Надалі перевіряти актуальний код.
- Переписування проєкту в modular monolith не заплановане; при розвитку
  наявних сервісів обговорювати користь і ціну їхнього розділення.

## Уточнення за вакансіями Capgemini, 2026-10-18

- Загальні пріоритети та практичні орієнтири збережені в
  [docs/DEVELOPMENT_PLAN.md](docs/DEVELOPMENT_PLAN.md). Враховувати їх при
  обговоренні розвитку; це не вимога реалізувати всі теми в поточній задачі.
- Користувач надав три описи: два майже однакові Banking та один .NET + Azure.
  Аналіз базується на наданих текстах, без перевірки активності вакансій.
- Посилити SQL з основ, вимірювання продуктивності, тести, надійність інтеграцій,
  CI/CD, спостережуваність, безпеку, документацію та пояснення рішень англійською.
- Azure поглиблювати через практику після базових backend-навичок; IaC,
  NoSQL і Kubernetes вводити за потребою. Не вивчати всі інструменти одночасно.
- Capital Markets — окрема вимога досвіду у Banking; Hotel Booking не замінює
  комерційний банківський досвід. Не припускати його наявності чи відсутності.
- Роки комерційного досвіду, освіта, англійська та досвід менторства користувача
  за цими описами не встановлені. Не робити висновку про відповідність вакансіям.

## Вибір Azure та фідбек Ciklum, 2026-10-20

- Користувач прямо обрав напрямок Azure Developer. Зберігати фокус на одній
  хмарі, не додавати паралельний AWS-трек через окрему вакансію.
- Рекрутер повідомив про вимогу комерційного AWS-досвіду для Senior .NET
  та його відсутність у резюме. Це не встановлює повну історію досвіду користувача.
- Наданий опис Ciklum .NET Engineer стосується AWS; Azure DevOps Pipelines
  у ньому — інструмент CI/CD, а не свідчення розгортання застосунку в Azure.
- Повідомлення рекрутера про Senior та опис із мінімум 2 роками й novice-рівнем
  не обов'язково стосуються тієї самої ролі. Не прирівнювати їх без уточнення.
- У наданому описі AWS Certified Developer – Associate вимагається протягом
  6 місяців від початку роботи. Це умова конкретної вакансії, не наша ціль Azure.
- Перенести до нашої Azure-практики спільні вимоги: automated deployment,
  Docker, керування доступом і секретами, моніторинг, комунікація й самостійність.
- Відрізняти навчальну хмарну практику, сертифікат і комерційний досвід;
  у майбутньому резюме описувати фактичний рівень та приклади чесно.
